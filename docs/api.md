# API Documentation

This document describes the restaurant and menu API provided by the project.

The API exposes restaurant information, operating hours, normalized restaurant tags, and menu items stored in the database.

---

# Endpoint

```text
https://userweb.cs.txstate.edu/~zld17/
```

The API returns JSON responses.

A successful response has the following general structure:

```json
{
    "status": "success",
    "server_time": "2026-01-01 12:00:00",
    "count": 1,
    "data": []
}
```

---

# Response Structure

## `status`

Indicates whether the request was processed successfully.

Possible values currently include:

```text
success
error
```

A successful request returns:

```json
"status": "success"
```

---

## `server_time`

Contains the server's current date and time when the response was generated.

Example:

```json
"server_time": "2026-01-01 12:00:00"
```

This value is generated by the API rather than stored in the database.

---

## `count`

Indicates the number of restaurant records returned in `data`.

Example:

```json
"count": 1
```

If no restaurants are returned:

```json
"count": 0
```

---

## `data`

Contains the restaurant records returned by the API.

Each restaurant object contains the restaurant's basic information, current operating status, today's hours, normalized venue tags, and menu items.

Example:

```json
{
    "id": 1,
    "name": "Example Burger Co.",
    "website_url": "https://example.com",
    "is_open_now": true,
    "today_hours": {
        "open_time": "11:00",
        "close_time": "22:00",
        "is_closed": false
    },
    "venue_tags": [
        "fast_food",
        "drive_thru",
        "mobile_ordering"
    ],
    "menu_items": []
}
```

---

# Restaurant Fields

## `id`

The unique database identifier for the restaurant.

Example:

```json
"id": 1
```

This corresponds to `restaurants.id`.

Restaurant IDs are database identifiers and should not be interpreted as an ordering or ranking.

---

## `name`

The restaurant's name.

Example:

```json
"name": "Example Burger Co."
```

Restaurant names are unique within the database.

---

## `website_url`

The restaurant's website URL.

Example:

```json
"website_url": "https://example.com"
```

This field may be `null` when a restaurant does not have a stored website URL.

---

## `is_open_now`

Indicates whether the restaurant is currently considered open.

Example:

```json
"is_open_now": true
```

This value is **derived by the API at request time** using the restaurant's stored hours and the server's current date/time.

It is not stored as a permanent database value.

A restaurant can therefore have different `is_open_now` values depending on when the API is requested.

---

## `today_hours`

Contains the restaurant's hours for the current day.

Example:

```json
"today_hours": {
    "open_time": "11:00",
    "close_time": "22:00",
    "is_closed": false
}
```

The fields are:

| Field        | Description                                          |
| ------------ | ---------------------------------------------------- |
| `open_time`  | Scheduled opening time                               |
| `close_time` | Scheduled closing time                               |
| `is_closed`  | Whether the restaurant is marked closed for that day |

If the restaurant is closed, `is_closed` is `true`.

---

## `venue_tags`

Contains the normalized `venue_type` and `features` tags associated with the restaurant.

Example:

```json
"venue_tags": [
    "fast_food",
    "drive_thru",
    "mobile_ordering",
    "delivery"
]
```

These tags come from the normalized tag taxonomy described in `docs/tags.md`.

Restaurant-level cuisine tags are represented separately from venue/features classification when applicable.

---

# Menu Items

The `menu_items` field contains the restaurant's active menu items.

Example:

```json
"menu_items": [
    {
        "id": 1,
        "name": "Classic Cheeseburger",
        "category": "Burgers",
        "price": 6.49,
        "is_active": true,
        "nutrition": {
            "calories": 520,
            "protein_g": 27,
            "carbs_g": 39,
            "fat_g": 28,
            "fiber_g": 2,
            "sodium_mg": 980,
            "serving_size": "1 burger"
        },
        "tags": [
            "burger",
            "beef"
        ]
    }
]
```

The remaining field descriptions and documentation remain unchanged from the previous version.

# Data Model

The API is backed by a SQLite database.

The primary tables are:

```text
restaurants
restaurant_hours
menu_items
item_nutrition
tags
restaurant_tags
item_tags
```

The relationships are:

```text
restaurants
    |
    +-- restaurant_hours
    |
    +-- restaurant_tags -- tags
    |
    +-- menu_items
            |
            +-- item_nutrition
            |
            +-- item_tags -- tags
```

This structure separates restaurant information, menu information, nutrition data, operating hours, and normalized classifications.

# API Design Principles

The API follows several principles:

1. **Preserve source information.**
   Restaurant names, menu item names, and menu categories remain representative of the source menu.

2. **Normalize cross-restaurant classifications.**
   Tags provide consistent classifications that can be used across different restaurants.

3. **Separate stored and derived data.**
   Values such as `is_open_now` are calculated from stored restaurant hours rather than permanently stored.

4. **Keep menu items independent.**
   Individual orderable items are represented separately from meals, bundles, and combinations.

5. **Allow incomplete data.**
   Optional information such as nutrition data or website URLs may be unavailable without invalidating the restaurant or menu item.

6. **Keep the API response predictable.**
   Responses use a consistent JSON structure so clients can process successful and unsuccessful requests without depending on HTML or database-specific output.
